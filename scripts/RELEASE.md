# Windows x64 release packaging

A plain `MAJOR.MINOR.PATCH` tag must match package.json, Cargo.toml and tauri.conf.json. The workflow builds and checks an Actions artifact, then publishes the ZIP and SHA-256 sidecar to the GitHub Release for that tag. Only the publish job has permission to write repository contents. Distribute the whole ZIP, not the EXE alone. The app requires the Windows WebView2 Runtime and the external TeX installation described in the app README; neither is redistributed.

To reproduce locally, use the PowerShell commands in `.github/workflows/release.yml` from the repository root. Python 3.11+, Node 24, the x64 MSVC Rust toolchain (including rust-docs), and Visual Studio C++ build tools are required. After `npm ci` and `cargo fetch`, packaging does not contact any service. `python scripts/release.py 0.1.0 --exe PATH --out DIR` also accepts an existing release build. Fixed entry order, timestamps and permissions make repeated packing of identical inputs deterministic; this is not a claim that MSVC produces identical binaries across machines.

## Notice inputs

- Browser runtime: the lockfile and installed packages for React, React DOM, Scheduler, Tauri API and PDF.js. Include Vite and Rollup notices conservatively for generated client helpers. Optional native Node canvas packages are not in the browser build.
- PDF.js 5.7.284: include CMaps, ICC profiles, both font licenses and the qcms, OpenJPEG and JBIG2 texts from the four directories copied by vite.config.ts. The worker and copied WASM/JS also use upstream code not identified by the top-level Apache license. Supplemental texts come from [PDF.js external/brotli](https://github.com/mozilla/pdf.js/tree/v5.7.284/external/brotli), [Mozilla's QuickJS wrapper](https://github.com/mozilla/pdf.js.quickjs), [QuickJS](https://github.com/bellard/quickjs), [webpack](https://github.com/webpack/webpack), and [Emscripten and its musl libc](https://github.com/emscripten-core/emscripten). Review these again when updating PDF.js.
- Rust: `cargo metadata --locked --offline` resolves the Windows target and `custom-protocol` release feature. Include original legal files from the target graph, conservatively including build-time crates, rather than guessing from Cargo.lock or treating SPDX expressions as notices. Include the toolchain's standard-library copyright report and license texts. Include the complete unmodified registry source for MPL-covered crates so recipients do not need to rely on an upstream source offer.
- Registry omissions: selectors uses the MPL 2.0 text also shipped by cssparser; alloc-stdlib uses the BSD text from the same author's companion alloc-no-stdlib package. The webview2-com packages use their [workspace MIT license](https://github.com/wravery/webview2-rs). Independently, their x64 static loader comes from [Microsoft.Web.WebView2 1.0.3800.47](https://www.nuget.org/packages/Microsoft.Web.WebView2/1.0.3800.47); preserve the SDK LICENSE and NOTICE and check the actual loader hash. The MIT wrapper license is not a substitute for the SDK terms.

When dependencies, resource-copy rules, targets or features change, review the inventory (including bundled code, notices and source obligations) before widening checks or replacing any supplemental texts.
